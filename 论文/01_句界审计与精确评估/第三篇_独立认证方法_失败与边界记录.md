## 1. 核心定位：独立认证是研究目标

第三篇的设想不依赖事件序列编码。我们希望构造另一条认证依据，与第二篇的语义符号写入和读回互补。但“新范式”“独立信号”和“互补保证”目前都是待验证定位，尚未形成可以单独发表的方法结果。

现有实现是 **SemStamp 上的精确认证评估链路**：以冻结原文和原划分为中心，枚举合法检测单元划分，使用动态规划求最小检测分数。它不使用 AMR、事件符号或事件序列解码，但仍依赖 SemStamp 的原划分、MPNet 句向量、LSH 区域和相邻单元评分。[算法与依赖合同](../../experiments/semantic_watermark_defense_plan_20261007/ALGORITHM_CONTRACT.md)

因此要区分：

| “独立”的含义 | 当前状态 |
|---|---|
| 不借用第二篇的 AMR 事件符号读出 | 现有认证链路具备这种实现上的分离 |
| 产生独立于原检测器的新认证信号 | 未实现；当前仍认证 SemStamp 的同一评分 |
| 在语义符号水印失效时继续成功 | 未验证；缺少同文、同攻击的配对结果 |
| 联合使用后具有可靠误报控制和额外收益 | 未验证；没有联合流程的校准与独立测试 |

链路分离不等于错误独立，也不自动推出互补。给已有评分增加 exact verifier，同样不能直接证明提出了新的认证范式。

## 2. 叙事起点与研究问题

本项目的语义事件路线依赖生成、事件抽取、AMR 解析、符号识别和对应关系恢复。任何环节失去一致证据，都可能使指定信息无法读回。既有 readout1 已观察到完整序列尚不能可靠恢复；这些结果提供研究动机，但不能推广为所有语义水印都会被所有语义改写攻破。[语义事件路线复盘](../../第二篇_语义消息写入与读回/02_实验/semantic_sequence_readout1/RETROSPECTIVE.md)

由此提出的问题是：

> 能否建立另一条认证链路，在明确的一类合法扰动内提供可核验保证，并在语义事件符号读回失效的部分样本上保留有效证据？

这个问题同时要求明确的保证集合、可接受的完整计算成本，以及真实文本上的认证成功率和误报控制。仅有算法正确性或一个高分样本都不够。

## 3. 拟评估的攻击与实际完成范围

原设想希望比较轻度复述、句式重组、局部事件改动与强语义改写。目前没有完成这组配对攻击实验。

| 扰动 | 现有合同是否覆盖 | 当前证据 |
|---|---|---|
| 固定原文字节，仅调整 detector 接收的单元边界 | 在冻结合法性与半径集合内覆盖 | 算法与资源准备有结果；真实证书未计算 |
| 表层复述、同义替换、语序改变 | 不在当前固定字节集合内 | 不能给出该攻击域的认证结论 |
| 修改标点形成表面拆句、合句 | 不在当前固定字节集合内 | 不能借用 detector-unitization 证书 |
| 局部事件改动、少量事件扰动 | 不在当前固定字节集合内 | 没有互补认证成功率或 FPR 结果 |
| 全局语义重写、替换核心事件、重构文本意图 | 不在当前固定字节集合内 | 现有保证不适用；没有本机制被攻破的实测结果 |

现有集合记为：

$$
\mathcal U_b(x)=\left\{B:\operatorname{legal}(x,B),
\max\bigl(|B\setminus B_0|,|B_0\setminus B|\bigr)\le b\right\},
$$

其评估对象是：

$$
C_b(x)=\min_{B\in\mathcal U_b(x)}D(B).
$$

这里插入或删除的是检测单元边界；字节、标点、词汇、词序和空白均不改变。只有完成真实评分、合法性与 witness 核验，并使用对应阈值时，才可能对这个集合内的所有划分给出证书。[威胁集合与统计合同](../../experiments/semantic_watermark_defense_plan_20261007/THREAT_MODEL.md)

“攻击强度适中”本身不是合法集合定义。未来若要覆盖复述或事件改动，必须另建明确的扰动合同；当前文稿不能把固定字节重划分改名为“中等强度语义攻击”。

## 4. 实际失败：未得到实用认证与互补证据

本轮未达目标包含三种不同问题。

**第一，保证范围没有达到原设想。** 当前实现处理检测单元划分，不处理文本内容变化。它尚不能承担局部复述或事件改动场景下的互补保证，也没有产生独立的新信号。这是方法范围与研究目标之间的缺口。

**第二，历史半径覆盖出现不一致。** v3 使用 `min(b,m0)`，使请求半径2的28篇、请求半径3的155篇被收窄。v4 已修正 Python 调度和 C++ 入口限制；完整3,000行计划从46,501层增加到47,332层。本地与Linux的系统实例、随机合法性、兼容性和纯插入检查通过，但新完整原生工作量尚未执行。[覆盖修正与检查](../../experiments/semstamp_certified_defense_v4_full_radius_profile1/CONCLUSION.md)

**第三，实用性门未通过。** 逐行核对旧3,000行账本并沿用冻结费率后，完整半径双重放的费用模型下界为 **75.3111小时**，超过72小时门限。当前环境还缺失原密封文本和冻结 tokenizer/Punkt。终态为 `V4_FULL_RADIUS_READINESS_STOP`，新全量 profile、检测评分和证书均未执行。[资源审计](../../experiments/semstamp_certified_defense_v4_full_radius_profile1/RESOURCE_AUDIT.json)

75.3111小时是冻结费用模型的预算下界，不是新实验的实测 GPU 时间。该 Stop 说明当前合同下未达到完整执行条件，不是实际跑完攻击后得到低认证率。

| 希望获得的结果 | 收口时的真实状态 |
|---|---|
| 新的独立认证机制 | 尚未建立 |
| 完整合法集合上的真实文本证书 | 未计算 |
| 轻度复述或局部事件扰动下较高认证成功率 | 未验证 |
| 语义符号读回失败、另一认证链路成功的配对证据 | 未验证 |
| 认证程序及联合程序的独立测试 FPR | 未获得 |
| 在冻结预算内完成完整认证 | 未达成，资源 Stop |

我们可以保留的正向工程结果是：覆盖差异已修正，合成 CPU oracle 与跨平台检查通过，资源账本可复核。这些不能替代“在局部改写下维持较高认证成功率”的正向结论。

## 5. 攻击边界与可以作出的结论

现有认证的形式化边界由固定原文、原划分、候选 gap、原生合法性和半径共同定义。只要攻击改变了这些前提，现有证书便不能直接覆盖该输入；这是一条保证适用范围，不需要把攻击命名为“强”或“弱”。

对全局语义重写、核心事件替换和意图重构，当前能够说的是：**它们不在现有保证范围内，不能继续援引同一证书。** 由于没有完成对应实验，不能进一步宣称已经证明独立认证信号被破坏。局部复述和小幅事件改动也同样未被当前合同纳入。

本轮失败也不证明所有独立认证方向均无效。它说明这一具体实现及执行条件尚未达到我们的研究目标。正式认证率、FPR和鲁棒半径仍是“未估计”，不能把未计算写成零，也不能以检测器原划分的健康结果代替认证结果。

## 6. 可直接用于文稿的失败陈述

> 我们探索了与语义事件符号读回解耦的认证链路，希望在部分水印失效场景中保留可核验的来源证据。本轮探索未能实现这一实用目标。现有实现通过精确动态规划评估固定字节上的检测单元划分，但尚未建立覆盖复述或事件变化的独立认证信号，也未取得两条链路互补的配对实证。虽然我们完成了半径覆盖修正、算法核验和资源审计，完整认证在冻结预算下未通过准备门，真实文本证书与对应的独立误报评估均未产生。因此，本文不声称已获得局部改写下的互补鲁棒保证，而将该方向作为未成功实现的探索记录，并明确其当前保证范围与工程局限。
