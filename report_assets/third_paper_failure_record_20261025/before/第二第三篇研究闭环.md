### 2.5 序列识别与多层次注意力怎样形成可检验的方法

先明确“载体”：每个符号需要对应能够核验的谓词—角色—实体结构，记录被复述后的稳定身份。同一个文本或规范图若可对应不同符号，就必须报告碰撞；扩大模型不能消除标签本身的歧义。

若 S1–S5 支持继续，建议在新版本中按以下接口实现方法候选：

```text
文本与角色证据
  → 局部事件表示、可用性掩码
  → 独立符号分类 / 轻量事件序列编码
  → 符号权重、背景与擦除输出
  → 声明通道下的对齐与消息解码
  → 独立新文本上的完整消息评价
```

**专门序列模型的候选位置是事件表示之后。** 可先选一个轻量事件级 Transformer，与同输入的独立分类器比较；只有上下文能改善符号错误、擦除或完整消息恢复，才保留序列模型。

**层次注意力的候选位置是局部证据与事件上下文之间。** 词/角色到事件的注意力聚合负责减少窗口背景；事件到上下文的注意力负责利用相互关系。AMR角色边可作为关系特征或约束。它们属于待实现结构，不是当前代码已经具备的能力。

最少消融应依次比较：同输入独立分类；同输入简单池化或门控；仅事件序列上下文；仅局部注意力；二者组合。共享载体、候选、训练样本、上游表示与尽可能匹配的参数/训练预算。新模板、新训练方式、负例筛选和注意力若同时改变，就无法把提升归因于注意力。

推理时禁止读取计划符号、目标模板、真实载体位置、真实事件数和扰动标签。训练监督可以使用这些标签，但不得把它们接入测试前向过程。模型产生的置信权重未经校准时不称为真实后验概率；注意力热图本身也不是机制证明。

### 2.6 顺序与消息恢复必须先统一定义

当前排序的是文本叙述顺序，不是事件发生时间。保留命题的复述可以交换叙述顺序；如果消息完全依赖表面顺序，那么允许任意保义重排就可能使源消息无法唯一识别。再加注意力不能自动解决这种信息歧义。

建议首先选择并冻结一种通道：允许词汇复述和自然拆合句，但对可对应载体的顺序变化作明确限制；事件插删、有限重排分别作为声明编辑条件。若改用语义因果或时间偏序编码，则需另立消息对象、关系标签、可识别性假设与解码规则，不能继续沿用旧2520排列的成功口径。

还需区分两类输出：

- **候选序列检索/已知密钥检测：**从冻结候选或密钥预期序列中比较，输出匹配分数。
- **盲消息恢复：**在规定帧结构和码本下，从文本输出消息；原消息只在输出封存后用于评估。纠错、帧同步和码率若引入，需明确冗余与可支持编辑。

readout1 证明的是有限等频候选的排序信号，尚未完成第二类输出。八个四类符号不能直接记为16位可部署净容量。

## 3. 第三篇：先产出真实证书，再检验证书选择目标

### 3.1 认证对象与保证范围

当前合同认证的是**固定 UTF-8 字节上的 detector-unitization 变化**。插入、删除、移动的是检测单元边界；字符、标点、词汇、词序、大小写和空白字节均不改变。因此它不覆盖修改标点的表面拆合句，也不覆盖复述。

最新有效 renderer 使用 v2 refined atoms，在冻结 NLTK 端点处细化原词块，并保留原字节、空白和零字节 gap 规则。v1 中“所有边界只能在 maximal non-whitespace spans 之间”的描述不能直接冒充当前 refined 合同。

设原边界为 $B_0$，候选边界为 $B$，定义插入数 $i=|B\setminus B_0|$、删除数 $d=|B_0\setminus B|$，机械预算为 $\max(i,d)\le b$。一次边界删除和一次新增可以合并视为一次 relocation。所有候选还须满足原生 tokenizer/context 合法性。

SemStamp 把单元映射到八个 LSH 区域，根据前一区域与密钥定义后一区域的接受集合。相邻单元命中总数为 $H$，相邻对数为 $m$，$\lambda=0.25$：

$$
D(B)=\frac{H-0.25m}{\sqrt{0.25\cdot0.75m}},
\qquad
C_b(x)=\min_{B\in\mathcal U_b(x)}D(B).
$$

DP 对所有合法最终 $m$ 分层求最小命中数，再精确比较归一化分数。它不是随机挑若干攻击，不是检测时寻找最高分，也不是符号序列识别网络。[算法合同](file:///Users/bytedance/AMR/experiments/semantic_watermark_defense_plan_20261007/ALGORITHM_CONTRACT.md)。

本轮另核出一个范围对齐缺口：资源协议和实现采用 $\bar b(x)=\min(b,|B_0|)$。逐行读取3000条 PROFILE_ROWS 后，请求半径2有28篇实际只计算半径1；请求半径3有155篇实际只计算半径1或2。原边界数为1的文档28篇，为2的文档127篇。主半径1没有被收窄。

原威胁合同的 $\max(i,d)\le b$ 允许纯边界插入。新增边界数不必受原边界数限制：只要最终跨度合法，原来一个边界也可能允许再插入两个边界。因此上述cap不能直接证明对原始请求半径2、3的全集覆盖。它遵守了资源阶段自己的协议，但资源协议与原始认证集合定义不是同一个对象。

### 3.3 必须拆开的阈值与 FPR 口径

| 程序 | 判定 | 能给出的保证 | FPR 对应对象 |
|---|---|---|---|
| 原 SemStamp | $D(B_0)>\tau_0$ | 原划分下的检测行为 | 原程序的独立 Null |
| 原程序的固定阈值认证，补充分析 | $C_b>\tau_0$ | 声明集合内全部划分都通过原阈值 | 证书事件包含于原检测事件；原检测 FPR仍需独立报告 |
| 原防御合同的主程序 | $C_b>\tau_b$，用同一个 $C_b$ 校准 $\tau_b$ | 全部合法划分的 $D(B)$ 都大于该半径阈值 | 最小值检测程序的独立 Null |

原防御合同主线选择第三行，每个半径在1000 calibration Null 的 $C_b$ 上取第951顺序统计量，严格使用 `>`。[威胁与校准合同](file:///Users/bytedance/AMR/experiments/semantic_watermark_defense_plan_20261007/THREAT_MODEL.md)。

若 $\tau_b$ 低于 $\tau_0$，则 $C_b>\tau_b$ 不自动推出所有分句通过原来的 $\tau_0$；最小值程序的 FPR也不自动变成“在 $\tau_b$ 下用任意单一分句检测”的 FPR。未来文稿应分别报告程序、阈值和 Null 身份。

对同一文本，$C_b$ 随半径扩大不增加；但不同半径各自重新校准 $\tau_b$ 后，可认证率不必单调。若报告单调的原检测鲁棒半径，应使用固定阈值及完整评分。当前未完成评分，半径和 certified rate 是“未估计”，不能记为0。

保证以冻结的原字节与 $B_0$ 为中心。输入改写后重新生成中心、或重新运行一个不同的最小值检测程序，不能直接援引同一证书。

### 3.4 从资源 Stop 到证书的执行闭环

| 顺序 | 必须完成的工作 | 核验与交付物 | 通过后才能做什么 |
|---|---|---|---|
| C1 新版本资源合同 | 先对齐请求/effective半径，再冻结完整样本、层数、精度、硬件和预算 | 原始集合与实际覆盖逐行对应；新readiness文档与SHA | 进入受控等价/吞吐预检 |
| C2 保语义优化 | 优先降低合法跨度特征计算成本 | stressed workload、fresh replay、region逐项等价及完整资源账本 | 对新实现重新做全量 score-blind profile |
| C3 全量可执行性 | 保留3000行、全部合法层与风险边界 | pair/span/内存/磁盘/双重放预算所有门通过 | 冻结正式评分阶段 |
| C4 baseline 证书 | 计算完整 Null与positive的 $C_0,C_1,C_2,C_3$ | region/score/witness、coverage、阈值、独立FPR及certified rate；双重放与独立审计 | 判断是否具有实用证书和防御提升空间 |
| C5 证书引导生成 | 只在开发集选择候选预算与质量门 | 同prompt共享候选池；全部选择终态与成本 | 冻结 pilot |
| C6 pilot与确认 | 先冻结 pilot；通过后运行独立确认集 | 配对certified-rate、质量非劣、FPR、clean TPR和完整分母 | 依据结果决定方法论文或防御论文定位 |

现有effective-radius账本包含67,001,110个去重后的合法特征文本，特征编码是主要预算项。仅针对这份既有账本，总体速度至少提高约7.80%才可能从77.6152小时降到72小时；若只改进特征项、其余项保持账本值，则特征吞吐需提高约8.53%。这只是预算算术，不是已测加速；原始半径全集修复后须重新估算，也不能据此保证后续生成与确认预算足够。

不能仅优化 DP 就假定整个预算已过门。batch128在大工作量上改变了 canonical batch64 的 LSH region；因此不能替换。浮点向量误差小也不等于离散 region 一致。排序、padding、batch组合和并行方式的改变都需核对冻结 scorer 的语义。

资源、优化和等价预检的新阶段必须与已停止版本分开。使用新硬件或预算时也应明确记为新合同，而非抹去旧 Stop。主集合不能靠删最长文本、删半径、删层、采样或截断来获得“exact已完成”。

### 3.5 哪一种生成选择才是新的防御候选

对同一个 prompt，先封存同样的完整文档候选池及独立质量门，再比较：

| arm | 选择规则 | 在论文中的作用 |
|---|---|---|
| A0 | 原系统单次完整输出 | 原始系统参考 |
| A1 | 同预算池中第一个质量合格候选 | 配对主基线 |
| A2 | 选择原划分 clean 分数最高者 | 排除“多生成几个取高分”的解释 |
| A3 | 合法复现的 SwordStamp-style 区域深度/余量规则 | 排除已有 margin/best-of-N机制 |
| A4 | 对全部质量合格候选完整求 exact $C_1$，选择最大者 | 待验证的证书引导生成 |
| A5，可选 | 近似分数选择，最终用 exact评价 | 资源消融；不能冒称A4 |

所有 arm 使用相同候选池、质量门和 $\tau_1$。A4 可以读取当前候选的 exact 选择分数；禁止的是用整个确认集的表现去调预算、质量门、阈值、策略或挑最优版本。选择得分的合法使用应与确认集泄漏分开描述。

若某个质量合格候选 exact 未完成，A4不能忽略它并在容易候选中选最优；对应 prompt保留在完整分母，记录不完整。A3若不能合法、准确复现，明确 `NOT_REPRODUCED`，不能以自创分数代替或宣称优于SwordStamp。[基线合同](file:///Users/bytedance/AMR/experiments/semantic_watermark_defense_plan_20261007/BASELINE_COMPARISON_CONTRACT.md)。

原 PLAN 中 RQ3/WP6仍有“近似选择”的设计文字，而 WP1 基线合同明确将 exact A4作为主防御候选。新执行协议应将近似选择明确限定为A5，不得把两种实现混写成一个“certificate-guided”方法。本文记录这一待对齐点，不修改历史冻结合同。

### 3.6 第三篇的成篇门与最终表图

原计划的主半径为1。防御门包括：robust certified rate≥20%，其单侧CP95下界>10%；相对配对baseline提升≥10个百分点，单侧95%区间下界>0；test Null的单侧CP97.5 FPR上界≤8%；clean robust TPR≥80%；至少200对确认文本的双人质量盲评，overall pass的非劣界不低于-5个百分点。[原计划 §6](file:///Users/bytedance/AMR/experiments/semantic_watermark_defense_plan_20261007/PLAN.md)。

5%是校准目标；8%是历史独立测试上界门，二者不能合并称为“FPR保证5%”。独立人类测试 Null仍需匹配最终程序，既有Null资产不自动代表人类来源。

基线合同还要求 A4相对A2有正增量，并报告与A3的差异；A3未复现时，创新性比较未闭合。上述历史门满足不等于录用或全局新颖性已成立；新协议应在运行前统一所有相关口径。

baseline certificate需先完整算出来。若已有可认证率很高，可能没有足够的生成改进空间；若大多为空，需解释问题是否在单位数、区域转移或载体，而不是马上启动大规模候选生成。只有计算成本、证书非空性和改进空间都支持继续，才进入A4研究。

建议主图表：固定字节边界集合与保证；exact DP正确性及新增增量；各半径certified rate与独立FPR；耗时/内存/覆盖；A1/A2/A3/A4配对提升与质量。旧oracle和v17结果可以作继承前置证据，不能代替这些新终点。

这篇的序列性来自相邻单元依赖，不需要消息识别网络。原 SemStamp模型内部有多层自注意力；本课题的新增方法是精确搜索和选择目标。若添加跨句全局注意力，单元 region或pair score可能依赖全局上下文，原 DP分解不再自动成立，需新的状态或证明。学习网络若只用于排序或构造可证明界、同时保留全集覆盖和最终exact核验，才可能成为独立的新加速候选；未经验证的预测不能裁掉合法路径。
