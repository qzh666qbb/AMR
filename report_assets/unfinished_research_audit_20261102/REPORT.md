### path0 为什么属于过早下结论

原协议的开发 Null 目标是 observed ≤1%，即每条件 ≤2/200，**不是归档 README 写的 0.5%**。path0 的 3/200 或 4/200 确实没有达到这个工作点目标，但这只支持该条件下的负面观察。

原协议还明确写了“baseline 低于目标不机械终止候选”“允许明确报告的 TPR/鲁棒性损失换取 FPR 改善”，最终分类包括权衡和样本不足。没有生成正例就不能测 TPR 和存活，因此不能从现有结果推出完整权衡、唯一噪声根因，或“应当使用 Hop Penalty”。归档摘要中的“理论误报率保证”也未由这些观测建立。

本次已在 [archive/README.md](../../archive/README.md) 添加日期明确的更正，保留旧文字用于追溯。这里不预告 path0 补跑后一定更好；原 Null 比较对它不利，补齐正例的价值是回答尚未回答的权衡。

## 7. 补做顺序与停止规则

1. **先完成 W01 已授权迁移续跑。** 它最直接回答“旧融合换到新数据是否仍有效”。必须等完整结果及两份最终审计，不能用原句 AUROC 代替迁移结果。
2. **P1 优先补 W02 与 W03 的最小闭环。** W02 先解决正常长度完整正例的生成/异常合同；W03 先明确冻结正例生成预算，再完成原两臂的 TPR/存活权衡。二者都保留旧 Stop 和全部分母。
3. **P2 优先 W08，再决定 W06。** 先取得真实语义与修订图证据，分清原图丢信息还是读出器误读，再训练新监督模型。W05 可复用基础标注，但其比较仍要独立定义。
4. **W04 在新开发分离成立后再做正式确认。** 已完成的 alpha-only 负结果不支持盲目全量重跑。
5. **W07 保留为历史缺口，暂不为凑完整度回头重跑。** 新事实载体已推进；它不能阻止 W01 的当前检测迁移，也不能被说成已验证成功。
6. **X01–X04 和 S01–S02 作为新立项选项。** 当前没有依据一次铺开。未知 Bank/黑盒要改变威胁模型，独立解析器/多 Bank 要改变系统与重新校准，认证还需资源和原始资产。

建议以后把三类状态明确分开：资源不足记可恢复暂停；证据/日志无法信任记本版本完整性停止；完成声明比较后才给范围明确的性能裁决。原协议既已冻结，其 Stop 仍保留，后继实现这些规则，不能倒改历史。
