# 句向量辅助 AMR 水印检测：实现与运行说明

日期：2026-11-04

已实现对应融合研究原型，包括真实模型运行、官方归一化与 S2Match Bank 核验、去重、三臂对照、重新校准和独立测试入口。当前继续执行完整短文本基准复评，协议见 `experiments/embedding_amr_benchmark_20261104/PROTOCOL.json`。按用户 2026-11-04 的修订，语义、事实对应和质量评审采用 API 模型或助手，并明确标注来源；不再设置人员评审前置条件。旧冻结审计保持历史记录，后续状态以新增结果为准。

## 1. 实际实现了什么

输入只有待测文本、冻结模型和目标 Bank。事件查询来自**当前待测文本的多尺度 AMR 观测**，不需要原始水印文本、原始句界、注入位置或目标答案。

1. 沿用已有词窗和表面句界候选生成器，默认几何预算 24。完整记录枚举数量、候选池截断数、预算遗漏数。
2. 对候选作 AMR 解析，绑定精确输入 SHA、原始输出及 beam 日志。默认仅使用 beam 0、无告警、图与往返检查有效的结果；解析上下文超限保留为无效观测。无法绑定的日志使本次运行停止。
3. 从合格 AMR 提取事件描述，以 MiniLM 编码事件描述和候选文本。每个事件按余弦相似度检索最多 4 个候选，默认下限 0.35。
4. 在候选**自身**的原始 AMR 中验证同一事件。使用精确带标签多重图同构，保留谓词、实体、角色、数值、否定、关系方向和重入。上层意愿、报告等语义作用域保留；只移除 `and/:opN` 并列和 `multi-sentence/:sntN` 多句组织外壳。
5. 按短片段优先、位置和固定索引排序选择证据。已选完整图占用其中全部可用事实身份；同事实、同原图或同片段不重复累加。选择不读取 Bank 分数。
6. 候选选择全部结束后，才对选中候选自己的图作 Bank 匹配。不会把查询事件所在原图的高分转移给另一个相似片段。

规则是保守的结构对应，本身不提供外部语义真值。自动解析错误仍可能产生自洽的错误图；自对应也不能独立证明解析正确。跨谓词同义替换、代词消解、被省略角色等可能被严格规则拒绝。当前版本会先解析所有预算内候选，不承诺减少解析成本。语义质量另用不含 Bank、分数或写入成功标签的模型评审检查。

“角色互换被拒绝”的测试含义是两张角色不同的图不会被当作同一事实对应，不是承诺整篇角色互换后必定判无水印。结构 Bank 可能同时匹配两张不同事实的图；水印身份和事实真假仍需分别解释。去重也只对自动图中可核实的身份成立，解析产生的不一致身份仍可能残留重复，须用独立事实标签检查。

编码器与解析器使用 FP32，本地模型加载，禁止静默截断；编码器执行数值重放检查。真实解析器先做一次精确双重放，检测结果每篇再做一次精确重放。候选/事件超过明确资源门时会擦除或停止，不能视为全部合法分句搜索，更不是鲁棒性证书。

## 2. 三个对照臂

| 输出键 | 候选选择 | 最终证据 |
|---|---|---|
| `amr_only` | 共同合格候选中按固定规则选择 | 候选自身 AMR 的 Bank 分数 |
| `embedding_amr` | 句向量检索后，再检查 AMR 对应 | 候选自身 AMR 的 Bank 分数 |
| `embedding_without_relation` | 检索后关闭对应核验，保留相同去重 | 候选自身 AMR 的 Bank 分数 |

三臂共用候选、解析准入、编码器上下文准入、Bank 和去重规则。第一臂不使用向量相似度，但采用共同准入集合；它不是未经任何处理的官方 SWAN detector。第三臂是对应核验消融，也不是 SemStamp 或独立的“句向量水印”。

默认 `--scorer official`：对应核验和事实去重使用原始 AMR，只有选中的证据图才进入官方 `normalize_amr_variables → generate_template_amr → normalize_amr_variables` 和 S2Match。每张选中图匹配完整 Bank，使用现有官方运行器的逐图逐模板种子、余弦相似度、cutoff=0.5、diffsense=0.5 和五次 hill-climbing。归一化及完整模板分数均精确双重放；诊断或分数异常使运行停止，不输出部分统计量。支持 Bank50、Bank100 等非空且无重复模板的 Bank，实例状态独立。

`--scorer structural` 保留 A0/A1 的 `SwanAMRBankScorer`，即概念、关系和两跳路径的结构特征匹配，供显式开发对照。两个适配器的指纹不同，阈值不能混用。**官方图评分不等于官方文档 z 检测器**：三臂仍采用下述新统计量，需要整体重新校准。

实际任务须传入目标私有 Bank 文件及其 SHA；含 `kind=watermarked` 的输入还须传 `--writer-bank-sha256`，且必须与检测 Bank 一致。此参数是工程身份绑定，真正的写入来源仍须由封存生成记录证明。公开 Bank100 只适合工程示例或明确标注的公开 Bank 实验。

文档统计量为：

$$
T = \frac{\sum_{g\in U}(\max_{b\in B}s(g,b)-0.65)}{\sqrt{|U|}},
$$

其中 $U$ 是固定规则选出的去重图集合，$B$ 是指定 Bank。保留低分图的负贡献，不按 Bank 分数筛选图。向量相似度不进入 $T$。若 $U$ 为空，输出 `statistic: null` 和 `status: abstain`。

## 4. 输入与运行

在 `/Users/bytedance/AMR` 工作目录运行。输入为 JSONL，每行严格包含以下七个字段：

```json
{
  "row_id": "human-cal-001-clean",
  "source_id": "human-cal-001",
  "source_sha256": "<原始来源文本的64位SHA256>",
  "condition": "clean",
  "kind": "human",
  "split": "calibration",
  "text": "<当前条件下的待测文本>"
}
```

`source_id` 和 `source_sha256` 必须在同一来源的所有条件下保持一致。`kind` 为 `human/watermarked/llm/synthetic`；`split` 为 `development/calibration/test`。元数据只用于运行记录和后置评估，不传给检测算法。真实人类语料的来源资格需由数据准备过程提供；字段写成 `human` 本身不构成来源证明。预定条件无法生成时保留该行，使用 `text: ""`；三臂必须全部 abstain，空文本不作为跨来源重复文本，仍计入完整分母。

从真实文本开始计分：

```bash
.venv/bin/python scripts/run_embedding_amr_detection.py score \
  --input /absolute/path/to/calibration.jsonl \
  --output /absolute/path/to/new_calibration_run \
  --bank /absolute/path/to/private_bank.json \
  --bank-sha256 <经核对的Bank文件SHA256> \
  --encoder experiments/swan_atomic_alignment_completion2/private/encoder \
  --device cpu
```

默认 AMR 资产来自 `models/model_parse_xfm_bart_large-v0_1_0` 和 `models/bart-large-tokenizer`，也可以通过 `--parser-model`、`--tokenizer` 显式指定。Linux GPU 运行可设 `--device cuda`；本命令不运行 SemStamp。

官方适配器还读取 `vectors/glove.6B.100d.txt`（可用 `--vectors` 指定）、本地 `en_core_web_sm` 和 `.nltk_data/corpora/propbank.zip`。这些资产及官方代码均写入指纹并在结束时核对 SHA。

需要仅重放当前运行器生成的封存 AMR 时，增加 `--replay /absolute/path/to/completed_run`。它会核对终态、清单、观测 seal、逐文件 SHA；缺图直接报错。此功能只允许 `development` 输入，正式 calibration/test 必须重新解析，评估入口也拒绝 replay 结果。

输出：

- `MANIFEST.json`：输入、模型、代码、依赖、Bank、参数及检测器指纹。
- `private/observations/`：原始 AMR 及绑定日志；`private/<row-hash>.json`：逐篇对应、拒绝和 Bank 证据。
- `private/BANK_AUDIT.json`：官方评分模式下，选中原图对应的归一化图 SHA、完整 Bank 分数及精确重放记录。
- `SCORES.json`：无原文的逐篇三臂统计量及完整行数。
- `OBSERVATION_SEAL.json`、`AUDIT.json`、`TERMINAL.json`：封存和完成证明。
- 失败时写 `HALT.json`，不产生成功终态；已存在的运行目录不可覆盖。

私有目录包含原始图及内容线索，不应随公开包分发。当前运行器支持完成后的重放，**尚不支持中断后的自动续跑**。

## 5. 重新校准与独立测试

先用独立人类校准数据跑 `score`，再拟合：

```bash
.venv/bin/python scripts/run_embedding_amr_detection.py calibrate \
  --scores /absolute/path/to/new_calibration_run/SCORES.json \
  --output /absolute/path/to/calibration.json \
  --alpha 0.05
```

对测试数据使用完全相同的参数、Bank 和模型另跑 `score`，然后：

```bash
.venv/bin/python scripts/run_embedding_amr_detection.py evaluate \
  --scores /absolute/path/to/new_test_run/SCORES.json \
  --calibration /absolute/path/to/calibration.json \
  --output /absolute/path/to/evaluation.json
```

各臂、各编辑条件分别使用完整新流程统计量校准：

$$
p(T)=\frac{1+\sum_{i=1}^{n}\mathbf{1}[T_i\geq T]}{n+1}.
$$

校准擦除作为负无穷保留分母，测试擦除不判水印且保留测试分母；并列使用 `>=`。目标 5% 至少需要 19 个独立校准来源，1% 至少需要 99 个。这只是可分辨该 p 值的最低样本量，不是统计功效充分的证明。

CLI 仅接受完整新运行的 `SCORES.json`：核对 TERMINAL 与 manifest/audit/scores/observation seal 的 SHA、全分母和检测器指纹。校准产物也带完整内容校验和，修改其中分数后无法直接评估。

校准与测试同时检查来源 ID、来源 SHA、待测文本 SHA 不重叠，包括“校准来源原文重新出现为测试条件文本”的跨字段情况；禁止正例进入人类校准、同一来源条件重复、缺条件行、非有限分数及检测器指纹漂移。测试必须包含独立人类无水印样本，分别输出各条件和各类样本的 FPR/TPR、完整分母、擦除数和 Clopper–Pearson 95% 区间。

新增两个固定配对比较：`embedding_amr − amr_only` 和 `embedding_amr − embedding_without_relation`。报告同篇不一致判定数、率差、保守点态 95% 率差区间、双侧精确 McNemar p，以及覆盖所有条件、样本类别和两个对照的 Holm 调整 p。率差区间对两类不一致概率分别构造 97.5% 精确二项区间，再通过 union bound 合成；可能较宽。正例率差为正有利，人类/LLM Null 率差为负有利，不能混淆。

这是按条件的边际校准，不能解释为跨条件同时误报控制；率和率差区间仍为点态区间，只有比较 p 做了 Holm 调整。当前没有从测试集选择“最优融合”、学习权重或性能胜出自动判定。正式论文还需独立事实对应标签、可信水印正例、同误报要求下的配对比较及预先冻结的功效方案。
