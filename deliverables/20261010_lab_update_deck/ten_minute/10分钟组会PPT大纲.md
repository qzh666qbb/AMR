## 第3页

【页面标题】  
研究背景：早期找到了攻击面，但没有找到诱因

【页面正文内容】

- SWAN 流程：分句 → BART AMR → 模板化 → S2Match → $z$ 统计
- Plan A 基线：AUROC 0.985，TPR@5% FPR 94.4%
- Plan B--D：图操作低分率约 20%--26.7%，质量通过率仅约 46%--50%
- Plan E：反馈搜索出现大量低分候选，但混入质量失败
- 核心缺口：**哪个变量真正触发检测下降？**

【汇报讲稿】  
前期我们从节点替换、边调整、重入拓扑一直做到反馈式联合改写。结果表明，
简单图操作会被重解析规范化，强图操作又容易破坏事实。Plan E 虽然找到了
大量低分候选，但不能区分句界、parser、模板匹配和统计聚合各自的作用。
老师上次提出的“寻找诱因”，正好击中了这个缺口。

【自我理解备注】

- 不要把 Plan E 的 249/250 说成有效攻击率，它只是至少一个低分候选的覆盖率。
- 导师可能问“为什么不继续设计更强 AMR 算子”：因为攻击效果与语义保真
  明显冲突，继续加扰动很可能只是在制造事实错误。

## 第4页

【页面标题】  
研究目标与创新思路：从“找攻击”转向“验证句界”

【页面正文内容】

**我提出并冻结的研究设计**

- 诱因假设：句界同时改变检测单元数 $N$ 与候选图作用域
- P1：固定词汇与词序，只改标点仍应改变判定
- P2：恢复原 detector units 后，判定应恢复
- P3：$N=1$ 的统计上限应低于阈值
- P4：固定模板库时，扩大候选图作用域应降低局部匹配
- 扩展目标：对合法 variable-$N$ 重分句求 exact worst case

【汇报讲稿】  
我的核心直觉是，句界不是普通文本特征，而是检测器接口的一部分。它一方面
决定统计样本数 $N$，另一方面决定每张 AMR 图覆盖多大文本范围。基于这个
直觉，我把问题拆成四个可证伪预测，并进一步提出对全部合法重分句求最坏值，
而不是只测几个手工攻击样本。

【自我理解备注】

- “创新”要说成证据组织与系统特异审计，不要声称首次提出句界攻击。
- AliMark、SwordStamp 已覆盖 split/merge、$N$ 效应和部分防御。
- 可守住的增量：SWAN 上固定模板库、固定词汇和词序、判定可逆翻转；
  以及完整 variable-$N$ exact 求解的工程验证。

实验结果：句界诱因得到确认，但认证证书未进入执行

【页面正文内容】

**Agent 流水线运行结果，以下指标经人工复核**

- 公平三臂：普通复述 6.7%，Plan E 53.3%，句界重组 100.0%

- 严格 A--B--A：`1/30 → 30/30 → 1/30`，双向 $p=3.73\times10^{-9}$
- 统计解释：$N=1$ 时 $z_{\max}=1.732<2.33$
- 图作用域诊断：中位 F1 `0.8197 → 0.4502`
- SemStamp v17：FPR 4.7%，TPR 95.4%
- v3 全量 profile：77.6152 GPU-hours > 72，certificate 未启动

【汇报讲稿】  
结果可以分成两部分。SWAN 方面，公平比较先把句界筛出来，严格 A--B--A
又证明判定能随句界可逆翻转。统计上，单单元的最高 z 已经低于阈值；图组合
诊断也显示更大作用域会稀释匹配。SemStamp 方面，detector health 是健康的，
variable-N core 也通过，但全量 profile 超过 72 小时，因此没有正式
certificate，更没有 certified TPR。

【自我理解备注】

- 结果必须说“由 Agent 流水线运行得到，经人工复核”，不要说“Agent发现机制”。
- 图组合是 scorer diagnostic，不是自然文本 parser 的无漂移反事实。
- `77.6152>72` 是 readiness Stop，不能解读为 SemStamp 不鲁棒。

## 第12页

【页面标题】  
当前问题与异常：流水线暴露了四类边界条件

【页面正文内容】

1. **外部有效性不足**：核心 A--B--A 仅 30 篇、平均 30.9 词
2. **正常长度未闭环**：23/30 可合并，但 0/30 有合格自然拆分点
3. **防御未通过**：局部证据、经验尾、motif 均未过预注册门
4. **实现异常被捕获**
   - v1：42/3000 个 NLTK 边界落入 atom
   - v2 WP4：runner 误用 fixed-$N$
   - v3：batch128 改变 region array
5. **资源超限**：完整 profile 超 72 小时 5.6152 小时

【汇报讲稿】  
当前问题不能只归结为算力。第一，核心因果结果仍是短文本。第二，正常长度
的句数守恒对照在构造阶段就失败。第三，SWAN 防御路线没有通过开发门。
流水线还抓到了 renderer、solver 调用和 batch 语义漂移三个实现问题。
最后才是资源超限。它们分别对应数据、方法、实现和算力，不能混为一个问题。

【自我理解备注】

- 42 条 renderer 冲突后来通过 refined atoms 修复，但 v1 Stop 仍保留。
- fixed-$N$ runner 的 83 行结果已封存，不能当 variable-$N$ profile。
- batch128 虽快 1.0333 倍，但改变 region，不能用于正式证书。
- 导师问“Agent 会不会跑错”：回答会，因此有冻结合同、双 replay、独立审计
  和 fail-closed Stop；自动化不等于无需审查。
